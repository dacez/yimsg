## 3. 前端验证入口

| 场景 | 命令 | 说明 |
|---|---|---|
| 全部前端构建 | `npm run build` | 依次构建 SDK、UIKit、官方 Web App 和 UIKit 示例 |
| UIKit 独立构建 | `npm run build -w @yimsg/uikit` | 仅验证可嵌入 UIKit 产物 |
| SDK 单元测试 | `npm run test:unit` | 覆盖 SDK transport、同步、存储与有界集合 |
| UIKit 单元测试 | `npm run test:uikit` | 覆盖 BoundedList 核心、UIKit 公开入口、视图 helper、布局、主题和安全 |
| SDK 集成测试 | `npm run test:sdk` | 需服务端可用，覆盖 WebSocket SDK 端到端调用 |
| UI 测试 | `npm run test:e2e` | Playwright 全项目入口；不指定项目时也会运行 BoundedList 性能项目 |
| BoundedList 浏览器专项 | `BOUNDED_LIST_STANDALONE=1 PLAYWRIGHT_WORKERS=1 npm run test:ui -w @yimsg/web -- tests/ui/bounded-list --workers=1` | 跳过账号、seed 和服务端，真实 Chromium 单 worker 执行 51 个功能用例与 6 个性能用例 |
| 全量验证 | `./tools/run_all_tests.sh` | 从仓库根目录执行，包含前后端功能测试；UI 固定为 `chromium` 项目并显式 `--retries=0`，含 BoundedList 功能并排除其性能 spec |

## 4. 维护约定

1. `前端设计方案.md` 负责前端整体分层、运行形态和装配关系；具体 API、嵌入接口、视图细节分别维护在 SDK、UIKit、UI 文档中。
2. `sdk接口说明.md` 是业务方可见 API 的权威说明；新增或调整 SDK 公开方法、事件、`ClientOptions` 时必须同步本文档。
3. `sdk设计方案.md` 解释 SDK 内部边界；修改 DataGateway、状态机、协议校验、缓存上限、内存边界或通知处理时优先同步该文档；修改消息、通讯录、屏蔽列表、免打扰或会话同步共同规则时先同步 `../同步机制方案.md`。
4. `UIKit方案.md` 解释嵌入契约；修改 `mount()`、`MountOptions`、`MountHandle`、构建产物或宿主回调时必须同步该文档。
5. `UI设计方案.md` 解释主应用和 UIKit 视图；修改 `packages/uikit/src/app/views/`、布局、有界消息流窗口、样式 token 或移动端交互时必须同步该文档。
6. 新增前端专题前先判断能否合并进现有“架构与装配 / SDK 与协议契约 / UI 与交互专题”分组，避免再次产生阶段性孤立文档。
7. SDK 后续所有设计必须遵守“内存严格可控”原则：新增长期状态、缓存、队列、分页、后台任务或事件载荷时，必须同步说明上限、淘汰策略或释放路径。
8. 修改 `packages/uikit/src/app/bounded-list/` 的参数、方法、事件、窗口不变量或性能阈值时，必须同步 BoundedList 设计、[`测试方案.md` §7](../development/测试方案.md#7-boundedlist-playwright-与性能专项) 和缺陷列表；缺陷关闭时保留原回归断言，并同步更新用例状态与缺陷证据。
