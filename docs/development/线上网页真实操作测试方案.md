## 1. 目标与边界

本方案只验证用户可见的真实网页行为，不以接口调用、SDK 调用或既有自动化用例替代操作结果。代码和既有用例只用于：

- 补全登录后、特定角色下或特定数据量下才出现的入口。
- 确认分页阈值、撤回时限、角色权限等测试边界。
- 在发现异常后辅助定位，不反向覆盖线上实际表现。

测试目标为 `https://yimsg.im/app/`。浏览器使用隔离的无痕测试会话，桌面布局为主，关键链路补测手机布局。测试产生的账号、好友、群、组织、消息和文件均使用 `qa260726` 前缀，禁止使用真实个人信息或真实文件。

## 2. 版本与证据

- 代码基线：`main`，提交 `2f1961d`。
- 线上版本：以页面真实可见功能为准；若线上与代码不一致，单独记录“部署版本差异”，不直接判定代码缺陷。
- 证据最少包含：时间、账号角色、入口、操作步骤、期望结果、实际结果。
- Bug 证据补充：截图、页面错误文案、必要的浏览器控制台错误、是否可稳定复现。
- 不记录登录 token；测试密码从环境变量 `YIMSG_MANUAL_TEST_PASSWORD` 提供，不写入仓库。

## 5. 功能清单与验收点

### 5.1 启动、认证与设置

- 首次启动：即时 / 持久存储模式，自动 / 桌面 / 手机布局。
- 注册：成功、重复用户名、必填校验、错误展示、注册后进入应用。
- 登录：正确密码、错误密码、不存在账号、退出后重登。
- 密码：缺少字段、旧密码错误、修改成功、旧密码失效、新密码生效。
- 设置：昵称展示和修改、头像上传、UID、模式标识、中文 / English 切换、退出登录。
- 持久模式：清除本地数据后重新拉取服务端数据；即时模式不显示清除数据入口。

### 5.2 通讯录与好友

- 好友、请求、用户搜索三个页签和导航红点。
- 搜索存在 / 不存在账号；发送带备注申请；发出申请不可重复操作。
- 接收方接受 / 拒绝；双方列表刷新；备注修改；删除好友。
- 删除好友的双边表现；删除后单聊历史和重新加好友表现。
- 通讯录关键字搜索、滚动分页、重排后无重复。
- 群收藏 / 取消收藏、群备注、组织入口浏览。
- 黑名单、会话免打扰状态及取消操作。

### 5.3 单聊

- 从通讯录进入；发送按钮、Enter、Shift+Enter、空消息。
- 纯文本、Emoji、Markdown、图片、文件。
- 图片预览；文件名称、大小、下载或打开。
- 发送中占位、成功替换、失败提示、输入框清空。
- 引用、单条转发、多选合并转发、转发到多个会话。
- 撤回成功、对端同步、超过时限后入口消失或操作被拒绝。
- 会话详情、备注、免打扰、屏蔽 / 取消屏蔽。
- 未读数、导航红点、打开清未读、会话按最新消息排序。
- 历史消息向上 / 向下拉取、回到最新、顺序稳定、无重复。

### 5.4 群聊与群管理

- 建群名称必填、至少一个成员、多成员建群。
- 群主和成员收发文本、Emoji、Markdown、图片、文件。
- `@成员`、成员搜索、`@全体成员`；单聊输入 `@` 不出现成员选择器。
- 群内引用、转发、多选转发、撤回和对端同步。
- 群详情、成员总数、群主标识、成员列表。
- 群主修改头像、添加成员、移出成员；普通成员权限限制。
- 新成员历史拉取与后续消息；被移出成员后续访问 / 收信表现。
- 群收藏、群备注、免打扰及取消。
- 群成员超过 40 人时的分页和搜索。

### 5.5 组织管理

- 创建组织、进入组织通讯录、空组织状态。
- 组织重命名、删除组织。
- 创建 / 进入 / 重命名 / 删除部门，多级部门面包屑。
- 添加 / 移除成员、设置排序值、展示职务。
- 授予 / 撤销管理员；所有者、管理员、普通成员的入口和权限差异。
- 组织成员在通讯录中的展示、排序和刷新。

### 5.6 搜索、同步与多页面

- 会话列表顶部全局搜索：联系人和聊天记录分区、无结果、跳转命中。
- 当前会话消息搜索：结果、跳转、高亮、关闭。
- 同账号多页面：发信、收信、未读清除和好友变更同步。
- 不同账号多页面：实时消息、通知后主动拉取、切换视图时追平。
- 页面刷新、网络短断 / 恢复、会话过期和重新登录。
- Persistent 刷新保留；Instant 刷新后从服务器重新拉取。

### 5.7 大量消息与界面稳定性

- 70 / 120 / 220 条消息的发送、接收、滚动、顺序、去重、会话预览和未读计数。
- 高速连续发送时按钮、输入框、发送中占位和最终状态。
- 多会话交替来信时排序、选中态和滚动锚点。
- 长文本、换行、Markdown、特殊字符和恶意 HTML 作为文本安全展示。
- 桌面三栏、手机会话列表 / 聊天 / 详情返回路径，长按消息菜单。

## 6. Bug 分级与通过标准

| 级别 | 定义 |
|---|---|
| P0 | 数据泄露、越权、不可逆数据损坏、核心服务完全不可用 |
| P1 | 登录、收发消息、好友、群或组织主链路无法完成 |
| P2 | 功能可绕过但结果错误、同步不一致、明显交互阻塞 |
| P3 | 文案、样式、弱提示、低频边界问题 |

用例只有在页面可见结果与另一账号或刷新后的服务端状态一致时才算 `PASS`。仅看到点击响应、Toast 或本地临时占位不算通过。
