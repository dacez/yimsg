## 3. 缺陷详情

### BL-BUG-001 [P1] [OPEN] `localPageSource` 并发 reset 缓存污染

- 环境：Windows，Chromium `149.0.7827.55`，Playwright `1.61.1`，独立 BoundedList browser harness。
- 对应用例：`apps/web/tests/ui/bounded-list/bounded-list.spec.ts` 中 `BL-BUG-001：localPageSource 并发 reset 的旧 loadAll 会污染新查询续翻缓存`。
- 参数与数据：本地数据源 60 条，`pageSize=5`，先后查询 `item-1` 与 `item-2`，首个 `loadAll` 被人为暂停到第二次 reset 完成之后。
- 前置条件：同一个 `localPageSource` 上存在两个并发 reset，旧查询请求晚于新查询返回。
- 步骤：
  1. 暂停下一次本地首页加载。
  2. 启动查询 `item-1` 的 reset。
  3. 在旧请求仍未完成时执行查询 `item-2` 的 reset。
  4. 释放旧请求，再向 forward 方向续翻。
- 期望：第二次 reset 胜出；之后所有续翻结果都只来自 `item-2` 查询。
- 实际：旧 `loadAll` 晚返回后覆盖 `localPageSource` 的共享 `entries`，后续续翻混入旧查询结果。
- 复现率：100%，稳定复现。
- 影响：快速修改筛选条件时，列表首屏与后续页可能属于不同查询，用户会看到错误或混合数据。
- 初步定位：`packages/uikit/src/app/bounded-list/page-source.ts` 的 `localPageSource` 把加载结果写入共享缓存，但没有查询世代或 requestId；上层丢弃旧 reset 的 DOM apply 不能阻止数据源缓存被旧请求写回。
- 临时绕过：调用方串行执行 reset，等待上一轮本地 `loadAll` 完成后再提交新查询；无法串行时，为每次查询重建独立 `localPageSource`。
- 自动化证据：该用例以 `test.fail(true, 'BL-BUG-001：旧 loadAll 晚返回会覆盖 localPageSource 共享 entries')` 固化，期望断言检查续翻后的每一行都包含 `item-2`。

### BL-BUG-002 [P1] [OPEN] 旧 `fetchByIdentity` 覆盖后续 reset

- 环境：Windows，Chromium `149.0.7827.55`，Playwright `1.61.1`，独立 BoundedList browser harness。
- 对应用例：`apps/web/tests/ui/bounded-list/bounded-list.spec.ts` 中 `BL-BUG-002：旧 fetchByIdentity 不应在后续 reset 后覆盖新窗口`。
- 参数与数据：20 条数据，`pageSize=10`，开启 `fetchByIdentity`；同一身份 `1` 的旧刷新值为 `stale-refresh`，后续 reset 值为 `fresh-reset`。
- 前置条件：定向刷新已经发出但尚未返回，此时列表完成一次更新的数据 reset。
- 步骤：
  1. 离开新鲜端并对身份 `1` 触发定向刷新。
  2. 暂停该 `fetchByIdentity`。
  3. 更新数据源并执行 reset，使身份 `1` 显示 `fresh-reset`。
  4. 释放旧的定向刷新。
- 期望：reset 建立的新窗口拥有更高世代，旧定向刷新结果必须被丢弃。
- 实际：旧定向刷新返回后仍 patch 当前窗口，把 `fresh-reset` 覆盖回 `stale-refresh`。
- 复现率：100%，稳定复现。
- 影响：资料更新、删除或重排后可能被更早的轻通知刷新覆盖，页面重新出现陈旧内容。
- 初步定位：`packages/uikit/src/app/bounded-list/bounded-list.ts` 的 `flushInvalidate()` 只在 Promise 返回时检查 `disposed`，没有捕获并核对 `requestId` 或独立 refresh 世代。
- 临时绕过：调用方在 reset 前等待未完成的定向刷新；或在 `fetchByIdentity` 包装层记录世代并主动丢弃 reset 之前的返回值。
- 自动化证据：该用例以 `test.fail(true, 'BL-BUG-002：定向刷新缺少 requestId/世代保护')` 固化，期望断言要求身份 `1` 最终仍为 `fresh-reset`。

### BL-BUG-003 [P2] [OPEN] `renderItem` 多平级元素只有首元素可交互

- 环境：Windows，Chromium `149.0.7827.55`，Playwright `1.61.1`，独立 BoundedList browser harness。
- 对应用例：`apps/web/tests/ui/bounded-list/bounded-list.spec.ts` 中 `BL-BUG-003：renderItem 多个平级元素应全部触发同一 identity 交互`。
- 参数与数据：3 条数据，每条 `renderItem` 返回 2 个平级 DOM 元素。
- 前置条件：用户点击同一数据项由 `renderItem` 返回的第二个平级元素内部节点。
- 步骤：点击身份 `1` 的第二个平级元素中的 `.bl-row-label`。
- 期望：同一条数据的任一平级渲染元素都映射到相同 identity，并触发一次 `onActivate`。
- 实际：只有返回数组首元素带 `data-bsw-key`；事件委托从第二个平级元素向上找不到 identity，`onActivate` 不触发。
- 复现率：100%，稳定复现。
- 影响：群聊消息这类“一条数据渲染发送者名 + 气泡行”的结构中，部分可见区域点击无响应。
- 初步定位：`packages/uikit/src/app/bounded-list/stream-window.ts` 的 `applyRender()` 只对 `elements[0]` 设置 `data-bsw-key`。
- 临时绕过：调用方让 `renderItem` 返回单一根节点，把原有多个平级元素包在该根节点内；或由调用方给额外平级节点自行绑定交互。
- 自动化证据：该用例以 `test.fail(true, 'BL-BUG-003：当前只有 renderItem 返回的首元素带交互 identity')` 固化，期望断言要求恰好收到一次 identity `1`、事件类型 `click` 的 `onActivate` 完整 payload。

### BL-BUG-004 [P1] [OPEN] 外部 `SelectionStore` 使 `selection.max` 失效

- 环境：Windows，Chromium `149.0.7827.55`，Playwright `1.61.1`，独立 BoundedList browser harness。
- 对应用例：`apps/web/tests/ui/bounded-list/bounded-list.spec.ts` 中 `BL-BUG-004：外部 SelectionStore 不应让 selection.max 静默失效`。
- 参数与数据：3 条数据，`selection.mode='multi'`、`selection.max=1`，同时传入未设置上限的外部共享 store。
- 前置条件：第一个条目已经选中，选择数量达到配置上限 1。
- 步骤：继续点击第二个未选条目。
- 期望：第二次选择被拒绝，第二项保持未选中，并触发超限反馈。
- 实际：外部 store 自身没有上限，组件配置的 `selection.max=1` 没有生效，第二项被选中。
- 复现率：100%，稳定复现。
- 影响：转发或建群等多选场景可突破业务配置上限，最终请求可能过大或被后端拒绝。
- 初步定位：`packages/uikit/src/app/bounded-list/bounded-list.ts` 在传入 `selection.store` 时直接复用该 store，`selection.max` 只在组件自己创建 `new SelectionStore(max)` 时生效。
- 临时绕过：创建外部共享 store 时显式传入与组件一致的上限，例如 `new SelectionStore(1)`；不要同时依赖外部无界 store 与 `selection.max`。
- 自动化证据：该用例以 `test.fail(true, 'BL-BUG-004：传入外部 store 时配置 max 未被执行')` 固化，期望断言同时检查第二项的 `data-selected` 仍为 `false`，并收到一次 `onExceed`。

### BL-BUG-005 [P2] [OPEN] prepend 后键盘焦点按 index 漂移

- 环境：Windows，Chromium `149.0.7827.55`，Playwright `1.61.1`，独立 BoundedList browser harness。
- 对应用例：`apps/web/tests/ui/bounded-list/bounded-list.spec.ts` 中 `BL-BUG-005：键盘焦点在 prepend 后应按 identity 保持而不是按 index 漂移`。
- 参数与数据：20 条数据，从第 5 条开始加载，`pageSize=5`；键盘当前聚焦身份 `6`。
- 前置条件：滚动容器拥有真实浏览器焦点，使用 ArrowDown 将组件焦点移到身份 `6`。
- 步骤：向 backward 方向 prepend 一页更早数据。
- 期望：重渲后继续以 identity `6` 为焦点。
- 实际：组件保留旧 `focusedIndex`，prepend 改变数组下标后，焦点 class 漂移到另一身份。
- 复现率：100%，稳定复现。
- 影响：键盘用户翻到上一页后会在没有提示的情况下跳到错误条目，随后 Enter / Space 可能激活错误对象。
- 初步定位：`packages/uikit/src/app/bounded-list/stream-window.ts` 在 `applyRender()` 中用旧 index 从新 `state.items` 读取 focused key，未在数据变化前保存原 identity。
- 临时绕过：存在键盘焦点时避免 prepend；或由宿主在翻页后清除并按原 identity 重新建立焦点。
- 自动化证据：该用例以 `test.fail(true, 'BL-BUG-005：focusedIndex 使用新数组同下标，身份会漂移')` 固化，翻页前后都要求唯一 focused id 为 `6`。

### BL-BUG-006 [P2] [OPEN] 缺少 `updatePill` 文案仍显示空白提示条

### BL-BUG-007 [P1] [OPEN] 非法 `pageSize` / `maxPages` 不快速失败

- 前置条件：调用方通过 JavaScript 或错误配置绕过 TypeScript 静态约束。
- 步骤：依次用三组非法分页参数构造组件。
- 期望：构造阶段同步、明确地拒绝所有非有限正整数分页参数，不创建实例或注册项。

- 复现率：100%，稳定复现。

### BL-BUG-008 [P1] [OPEN] source 单页超过 limit 可突破窗口硬上限

- 环境：Windows，Chromium `149.0.7827.55`，Playwright `1.61.1`，独立 BoundedList browser harness。

- 参数与数据：100 条逻辑数据，`pageSize=10`、`maxPages=2`，测试 source 故意在单页额外返回 50 条。
- 前置条件：数据源违反 `limit` 约定，返回条目数大于请求上限。
- 步骤：mount 并完成首页加载，读取组件状态 count 与真实 DOM 行数。
- 期望：组件防御性维持 `pageSize×maxPages=20` 的硬上限，状态与 DOM 均不超过 20。
- 实际：`PageWindow` 信任 source 返回的 `items` 长度，单页即可超过整个窗口上限。
- 复现率：100%，稳定复现。
- 影响：服务端、适配器或本地 source 的单次异常可绕过组件最核心的内存和 DOM 有界不变量。
- 初步定位：`packages/uikit/src/app/bounded-list/page-window.ts` 只按页数裁剪，不验证或裁剪单页 item 数量。
- 临时绕过：所有 `PageSource` 适配器在返回前按请求 limit 防御性切片，并保证游标语义与切片后的页面一致。
- 自动化证据：该用例以 `test.fail(true, 'BL-BUG-008：PageWindow 当前信任 source.items 长度，未做防御性截断')` 固化，状态 count 与 DOM 行数均要求不超过 20。

### BL-BUG-009 [P1] [OPEN] tail 已贴底时内容 load 增高后不再贴底

- 环境：Windows，Chromium `149.0.7827.55`，Playwright `1.61.1`，独立 BoundedList browser harness。
- 对应用例：`apps/web/tests/ui/bounded-list/bounded-list.spec.ts` 中 `BL-BUG-009：tail 已贴底时内容 load 增高后仍应贴底`。
- 参数与数据：20 条数据，`pageSize=20`、`freshEdge='tail'`、`settleFrames=1`；最后一行异步增加 300px 高度并派发真实 load 事件。
- 前置条件：内容增高前列表距离底部为 0，用户确实处于 tail 新鲜端。
- 步骤：扩大身份 `19` 的行高、派发 load，并等待两个动画帧。
- 期望：组件识别“加载前已经贴底”，内容高度变化后继续将距离底部保持在 1px 以内。
- 实际：内容增高后 scrollTop 不再调整，用户被留在新底部上方。
- 复现率：100%，稳定复现。
- 影响：聊天图片、头像或富内容加载完成时，正在看最新消息的用户会被动离开底部，新消息可能落到视口之外。
- 初步定位：`BoundedStreamWindow` 已捕获 content load，但 `BoundedList` 构造它时没有连接 `onContentLoad`，因此 load 事件没有任何贴底动作。
- 临时绕过：宿主预留媒体尺寸；或在内容 load 时自行判断加载前是否贴底并设置 `scrollTop=scrollHeight`。
- 自动化证据：该用例以 `test.fail(true, 'BL-BUG-009：BoundedList 未连接 BoundedStreamWindow.onContentLoad')` 固化，期望断言要求 load 后 `distanceToBottom<=1`。

### BL-BUG-010 [P0] [OPEN] `upsertLocal` 重复 identity 且连续插入无硬上限

## 4. 状态与关闭规则

| 状态 | 含义 |
|---|---|
| `OPEN` | 已稳定复现，尚未提交修复 |
| `FIXING` | 已有在途修复，但失败断言仍存在 |
| `FIXED_WAIT_RETEST` | 修复已提交，尚未在规定浏览器环境完成定向与全量复测 |
| `CLOSED` | 移除对应 `test.fail` 后原断言通过，且 `./tools/run_all_tests.sh` 全量通过 |
| `BLOCKED` | 复测缺少必要环境或外部条件；必须写明阻塞原因 |
| `DESIGN_EXPECTED` | 经产品契约确认属于设计行为，不再按缺陷处理；保留重新定性的依据 |

关闭缺陷必须在同一变更中完成以下事项：

1. 保留原失败断言并移除对应 `test.fail`，不得用删除、放宽或 skip 测试代替修复。
2. 记录修复提交、Chromium / Playwright 版本、定向复测结果与全量测试结果。
3. 将摘要表和详情状态同步改为 `CLOSED`。
4. 若产品契约发生变化，先更新设计与测试期望，再把状态改为 `DESIGN_EXPECTED`；不能仅因现有代码如此表现就重新定性。
