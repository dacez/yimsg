### 1.1 本轮（2026-08-17 源码复审）新登记并关闭

四条都由源码复审发现，回归落在单元层；`../../../../docs/archive/BoundedList缺陷列表.md` 是 2026-08-13 的冻结快照，不再追加，所以这一轮的复现与修复摘要留在本文。

| ID | 严重度 | 状态 | 缺陷与修复摘要 | 回归用例 |
|---|---|---|---|---|
| `BL-UNIT-BUG-027` | P2 | CLOSED | 行复用判据按 `reuseUnchangedRows` 分成两套：内部数据更新那条**不检查条目是否相等**，于是「条目数据变了但 `renderItem` 产出的 DOM 恰好一致」时保留旧节点，宿主挂在旧节点上的监听仍闭包着旧数据。统一为「条目数据一变就换节点」，两种模式同一判据。 | `renderer` A7b/A7c |
| `BL-UNIT-BUG-028` | P2 | CLOSED | `removeLocal` 对只存在于 `pinnedItems()` 里的身份无效：`overlay.apply` 只作用于权威窗口，pinned 由 `visibleItems()` 单独拼接，于是该方法返回 `true` 却删不掉，下一帧又被钉回来。`LocalOverlay` 增加 `isDropped(id)`，pinned 段一并过滤。 | `bounded-list` H1b/H1c |
| `BL-UNIT-BUG-029` | P2 | CLOSED | 后台追平失败与首屏失败共用 `onError` 的 `'reset'` 阶段值，宿主无法区分「用户面前没内容」和「旧内容还在、只是没追上」，消息列表因此在网络抖动时弹出「加载消息失败」。新增 `'catchup'` 阶段值，保留窗口的首页请求失败时上报它。 | `bounded-list` J1b |
| `BL-UNIT-BUG-030` | P3 | CLOSED | `SelectionStore.replaceSingle` 在选中集已经正是该项时仍 `notify()`，单选列表里重复点同一行会触发整表重跑 `renderItem`。与同文件的 `delete` / `clear` 对齐，无变化即不通知。 | `selection` C1b/C1c |

## 2. 状态与维护规则

| 状态 | 含义 |
|---|---|
| `OPEN` | 已在真实 Chromium 稳定复现，尚无通过的正确期望回归 |
| `FIXED_PENDING_VERIFY` | 已有修复，但目标浏览器、性能门禁或全量回归尚未完成 |
| `CLOSED` | 正确期望的普通回归已通过，且没有 `test.fail` / `skip` / `fixme` 掩盖 |
| `DESIGN_EXPECTED` | 经契约确认属于设计行为，并保留重新定性的依据 |

新增缺陷时必须同时记录稳定编号、严重度、环境、前置条件、步骤、期望、实际、影响、定位和可执行回归。关闭缺陷时必须：

1. 保留原正确期望断言，移除临时 `test.fail`。
2. 同步本文总览、测试矩阵和设计契约；复现、修复摘要与关闭证据写进 §1.1（归档文件已冻结，不再追加）。
3. 运行 33 项功能专项、6 项性能专项以及仓库全量测试；全量脚本通过 `run_component_tests.sh` 包含功能专项，但性能专项仍由 `run_performance_tests.sh` 独立执行。

产品缺陷继续使用 `BL-BUG-NNN`；测试夹具、调度和断言自身的缺陷使用 `BL-TEST-BUG-NNN`，不得把测试基础设施问题记成产品缺陷，也不得用降低 worker 或增加 retry 作为关闭依据。
