## 1. 分工：谁测什么

三层测试的边界是硬的，同一个行为只在一层验证，不重复：

| 层 | 位置 | 只放什么 |
|---|---|---|
| Vitest 单测 | `packages/uikit/tests/unit/bounded-list/` | 纯逻辑：窗口记账、本地层叠加、追平决策、请求竞态、错误分支 |
| Playwright 组件测试 | `apps/web/tests/component/bounded-list.spec.ts` | 只有真实浏览器才有意义的：真实布局几何、真实事件派发、真实 DOM 节点身份、真实 rAF 时序 |
| Playwright 性能门禁 | `apps/web/tests/performance/bounded-list.performance.spec.ts` | 超大数据量下的耗时与内存上界 |

不在本方案范围内：宿主视图怎么用组件（各视图测试覆盖）、SDK 分页接口本身（SDK 单测与服务端 E2E 覆盖）。

## 2. 单测环境

### 2.1 为什么是手写 fake DOM

仓库的 vitest 跑在 node 环境，没有装 jsdom。组件的绝大多数行为只需要**可控的**元素与事件模型，不需要真实布局引擎——反而是「布局由测试精确编排」让锚点公式这类断言变得可能。`fake-dom.ts` 因此手写了一套最小 DOM。

代价是必须显式模拟浏览器会自动做的事：`scrollHeight` 不随内容增长、节点移动不影响布局、`getBoundingClientRect()` 返回测试写死的矩形。

### 2.2 fake DOM 能力清单

| 导出 | 能力 |
|---|---|
| `FakeElement` | `className` / `classList`、`textContent`、`appendChild` / `insertBefore` / `removeChild`、`isEqualNode`、`parentElement` / `children`、属性增删查、`scrollTop` / `scrollHeight` / `clientHeight`、可写的 `rect` + `getBoundingClientRect()`、监听增删 + `listenerCount(type)` + `dispatch(type, extra)` |
| `FakeWindow` | 监听增删与 `listenerCount` / `dispatch`，用于验证 window 级 pointer 兜底监听被注销 |
| `FakeDocument` | `createElement()`；`{ withView: false }` 模拟 `ownerDocument.defaultView` 为 null 的宿主 |
| `stripBoundingRect(el)` | 抽掉 `getBoundingClientRect`，落到锚点的降级分支 |
| `capturedListeners(el, type)` | 取出已注册的监听器本体，用于「注销之后仍被残留调用」这类白盒断言 |
| `viewOf(doc)` / `asElement` / `row` | 取 defaultView、类型桥接、快捷行构造 |

**`listenerCount` 是关键能力**：内存泄漏回归不能只断言「不再触发」，必须断言监听器真的被移除了。

### 2.3 共用测试数据源

`test-sources.ts` 提供五种数据源：

| 工厂 | 语义 | 典型用途 |
|---|---|---|
| `createInstantSource(getAll, { withTotal })` | 每次 fetch 重读 `getAll()`，`hasMore` 按真实剩余量精确判定 | 常规分页、模拟「服务端数据会变」 |
| `createAnchoredSource(getAll, anchorIndex)` | 首页从 `anchorIndex` 起切，两端都可能还有更多 | 双向续翻、双向裁剪 |
| `createOptimisticSource(getAll)` | 满页时**乐观**认为还有更多，只有真拿到空页才收敛 | 「续翻拿到空页」路径 |
| `createControllableSource()` | 手动控制每次 fetch 的 resolve / reject 时机 | 并发丢弃、错误处理、在飞状态的精确断言 |
| `createControllableFetcher()` | 手动控制 `fetchByIdentity` 的 resolve / reject | 定向刷新的竞态与失败路径 |

真实 keyset 分页在拿到一整页之前无法确定是否已到末尾，所以 `createOptimisticSource` 更贴近服务端行为；`createInstantSource` 的精确判定只是为了让与分页无关的用例好写。

### 2.4 两个容易踩的环境陷阱

**① `scrollHeight` 不随内容增长。** 默认 host 把它设成 `100000`（远大于 `clientHeight`），否则「内容不足一屏 → 双端都判定触界 → 链式补页」会在与分页无关的用例里意外触发。需要验证链式补页的用例才显式编排几何。

**② `reset` 默认 `pinEdge: true` 会把 `scrollTop` 摁到新鲜端。** 只想观察某个单点行为的用例用 `reset({ pinEdge: false })`，或在 reset 之后显式 `scrollTop = 500`。

## 3. 被测不变量

| # | 不变量 | 主要守护用例 |
|---|---|---|
| I1 | 渲染行数 ≤ `pageSize × (maxPages + 1)`（窗口 + 本地层），与数据总量无关 | `page-window` 硬有界、`overlay` 上限、`stress` A/C2 |
| I2 | DOM 条目节点数 == `state.count` | `stress` A1/D3、组件测试 |
| I3 | 同一身份在渲染序列里至多出现一次 | `page-window` 跨页去重、`bounded-list` G3/H1、`stress` D2 |
| I4 | 续翻只使用来自保留页的游标；拿不到锚点就不发请求 | `page-window` 续翻段、`bounded-list` C8、`stress` B2 |
| I5 | 过期响应一律整体丢弃，不触发任何回调 | `bounded-list` B4/K2、组件测试「后发 reset 胜出」 |
| I6 | 自动补页在任何服务端行为下都必然终止 | `bounded-list` C5/C6/C7/J3、`stress` B1 |
| I7 | 本端写入永远立即可见，且不被任何在飞响应吞掉 | `bounded-list` G1–G8 |
| I8 | 提示条只由追平决策点亮 / 熄灭，不会闪动 | `bounded-list` E7、组件测试「回归：提示条不闪」 |
| I9 | `dispose()` 之后监听全部归零、提示条 DOM 摘除、排队的帧任务不再触碰 DOM | `bounded-list` K1–K3、`renderer` J1–J3、`stress` E1/E2 |

## 6. 性能门禁

`apps/web/tests/performance/bounded-list.performance.spec.ts`，**6 个用例**，`chromium-performance` 项目、单 worker、零重试，由 `./tools/run_performance_tests.sh` 独立执行（不进常规全量正确性门禁）。

| 用例 | 门槛 |
|---|---|
| 本地 100,000 条过滤排序首屏 | P95 ≤ 1500ms，DOM ≤ 200 |
| 逻辑 1,000,000 条连续翻 250 页 | 单页 P95 ≤ 100ms，窗口恒 ≤ 500 |
| 200 行窗口连续本端写入 200 次 | P95 ≤ 50ms，无 DOM 增长 |
| 同一任务 10,000 次 invalidate | 只触发一次追平请求 |
| 创建与 dispose 300 次 | 注册表归零，强制 GC 后堆增长 ≤ 16MiB |
| 连续 1,000 次 upsertLocal | 渲染序列 ≤ `pageSize × (maxPages + 1)` |

阈值与结果口径见仓库 [`测试方案.md` §6](../../../../docs/development/测试方案.md#6-boundedlist-playwright-与性能专项)。

| 指标 | 结果 |
|---|---|
| Statements | **96.01%**（819 / 853） |
| Branches | **91.08%**（480 / 527） |
| Functions | **98.13%**（158 / 161） |
| Lines | **98.88%**（710 / 718） |

未覆盖的是少量运行时降级分支（无 `classList` 的宿主、无 rAF 的 `nextFrame` 分支等）。`index.ts` 与 `types.ts` 没有可执行语句。

## 8. 执行方式

```bash
# 只跑 bounded-list 单测
cd packages/uikit && npx vitest run tests/unit/bounded-list

# 带覆盖率
cd packages/uikit && npx vitest run \
  --coverage.enabled --coverage.provider=v8 \
  --coverage.include='src/app/bounded-list/**' \
  --coverage.reporter=text tests/unit/bounded-list

# UIKit 全量单测（仓库根目录）
npm run test:uikit

# 真实 Chromium 组件测试（仓库根目录）
./tools/run_component_tests.sh

# 独立性能门禁（仓库根目录）
./tools/run_performance_tests.sh

# 仓库全量正确性测试（仓库根目录）
./tools/run_all_tests.sh
```

改 `bounded-list/` 源码后至少要跑单元、组件、性能三个入口，再以 `./tools/run_all_tests.sh` 收口；改动涉及宿主接线（`app-instance.ts` / `main-app.ts`）时，E2E 分类会同时覆盖真实 Web 宿主。
